# PTMonitor

A minimal macOS **menu bar** app for watching private tracker (PT) torrent
clients: qBittorrent and Transmission. It lives in the menu bar (no Dock icon,
no window at launch), polls your servers on a fixed interval, and shows a
dropdown panel with one section per server: per-torrent name, progress,
speeds, and ETA.

![](build/icon-preview.png)

## Features

- **Menu bar agent** — accessory app (`LSUIElement`): no Dock icon, no window.
- **Multiple servers** — add any number of qBittorrent WebUI or Transmission
  RPC endpoints; each gets its own section in the panel.
- **Per-torrent rows** — two-line layout: name at full width, progress pill +
  speeds + ETA underneath, sorted by a fixed order (design §6.1).
- **Resilient polling** — one `Task` per enabled server; transient failures
  retry quickly, while healthy servers respect the user-configured interval
  (1–60 s).
- **Keychain-stored secrets** — passwords are never in `UserDefaults`; they go
  to the Keychain, keyed by server id.
- **HTTPS + self-signed certs** — `NSAllowsArbitraryLoads` style transport
  option exposed per server ("allow insecure").
- **Bilingual** — English and Simplified Chinese (en, zh-Hans), with a
  build-time check that both `.strings` files carry the same key set.
- **Builds with Command Line Tools only** — no Xcode project, no xcodebuild,
  no asset catalogs. SwiftPM from top to bottom.

## Requirements

- macOS 12 or newer
- Swift 5.7 toolchain (Xcode Command Line Tools are enough: `xcode-select --install`)
- `python3` (only for the localization check and the fake server script)

## Building

### Debug build (fast iteration)

```sh
swift build
.build/debug/PTMonitor          # runs the menu bar agent
```

### Release app bundle

Assembles an ad-hoc-signed `build/PTMonitor.app` (binary + icon + both
localizations + rendered Info.plist). The script is idempotent — each run
recreates the bundle — and fails the build if the two language files drift:

```sh
./scripts/build-app.sh
open build/PTMonitor.app        # or launch it from Finder
```

To change the version, edit `APP_VERSION` in `scripts/build-app.sh`
(it is rendered into `Info.plist` at bundle time).

## Running / using the app

1. Launch `PTMonitor.app` (or `.build/debug/PTMonitor`).
2. Click the menu bar icon to open the panel; use the footer row to add a
   server.
3. In the server editor pick a type (qBittorrent / Transmission), host, port,
   credentials, HTTPS/insecure toggles.
4. Base URL shortcuts: qBittorrent WebUI `/api/v2`, Transmission RPC
   `/transmission/rpc` — hosts may be given as bare host names, IP, or URL.

Poll interval is global (1–60 s, adjustable in Preferences); each enabled
server gets one polling task. Failures are surfaced as cause-specific,
localized headlines per server, with the technical diagnostic underneath.

## CLI (no GUI)

The binary has headless modes useful for development and diagnostics:

```sh
# Run all built-in checks (no XCTest needed under CLT), exit 0/1:
PTMonitor --selftest
# → selftest: OK (N checks passed)

# Fetch one snapshot from a server as JSON (exit 0 ok / 1 server fail / 2 usage):
PTMonitor --probe <qbittorrent|transmission> --host <host> [options]
```

Probe options:

| Flag | Meaning | Default |
|---|---|---|
| `--probe <type>` | `qbittorrent` or `transmission` | required |
| `--host` | host name, IP, or full URL | required |
| `--port` | server port | 8080 (qb) / 9091 (tr) |
| `--user`, `--pass` | credentials | — |
| `--https` | use HTTPS | off |
| `--insecure` | accept self-signed certificates | off |

Example against a fake server (no NAS needed):

```sh
python3 scripts/fake-qbittorrent.py            # stub qBittorrent 4.6 WebUI on :18080
.build/debug/PTMonitor --probe qbittorrent \
  --host 127.0.0.1 --port 18080 \
  --user admin --pass adminadmin
```

The fake server mirrors qBittorrent's exact auth behaviours (IP bans at 5
failed attempts, HTTP 403 for private endpoints without an `SID` cookie), so
transport bugs look like what they are instead of like "the server banned this
IP".

## Checks & development notes

- **`swift test` is intentionally absent** — XCTest is unusable under bare
  Command Line Tools (`error: XCTest not available`). Automated checks live in
  `Sources/PTMonitorCore/Diagnose/SelfTest.swift` and run via
  `PTMonitor --selftest`. Keep new pure-logic checks there.
- **Localization drift guard** — `scripts/check-localization.py` (invoked by
  `build-app.sh`) fails the build when `en.lproj` and `zh-Hans.lproj` disagree
  on keys. When adding a string, add it to both files.
- **Regenerating the icon** — edit and run `scripts/make-icon.swift`
  (it writes `Resources/AppIcon.icns` from `build/AppIcon.iconset`).
- **Signing** — the bundle is ad-hoc signed (`codesign --force --sign -`);
  for distribution you'd re-sign with a Developer ID and notarize.

## Tests via the probe

Since there is no XCTest target, end-to-end verification is done by pointing
the probe at the stub or a real server and checking the printed JSON snapshot.
See the "fake qbittorrent" example above.

## Localization

Primary languages: English (source of truth for keys) and Simplified Chinese.
Strings live in `Resources/{en,zh-Hans}.lproj/Localizable.strings`; the app
follows the system language unless overridden in Preferences (`AppLanguage`).
A language change takes effect after the automatic restart.

## Theme / design

Design decisions referenced as `§N` throughout the comments come from the
in-repo design documents under `.trellis/` (see `AGENTS.md` for how the
project is managed). Key constraints: menu-bar-only agent (R1), no user-facing
sort UI (R8), localized failure headlines (R6), nil ETA renders as an em dash
(AC17).
